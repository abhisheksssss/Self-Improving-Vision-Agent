Executive Summary

Autonomous Graphical User Interface (GUI) computer-use agents represent the next frontier in artificial intelligence, bridging high-level natural language human intent with complex digital operating environments. However, contemporary vision-based computer control agents (such as Anthropic Computer Use API, OSWorld baselines, and commercial RPA scripts) suffer from critical structural deficiencies: perception coordinate drift, open-loop execution failure loops, cross-session amnesia, platform fragmentation (Web vs. Desktop), and prohibitive inference token costs.

SIVAC (Self-Improving Vision Agent for Autonomous Computer Use) resolves these failure modes through an integrated multi-modal closed-loop paradigm. SIVAC unifies a hybrid perception engine (VLM visual grounding, local OCR fallback, Playwright browser DOM, and Windows UI Automation), a closed-loop verification and autonomous recovery state machine governed via LangGraph, and a dual-layer self-improvement memory architecture (SQLite structured trajectory logs and ChromaDB semantic vector store). This report establishes the complete problem definition, stakeholder needs, functional/non-functional specifications, and traceability framework.

Key Architectural Decision: SIVAC decouples high-level reasoning from hardware coordinates. The planner targets semantic element identifiers (e.g., target_id: "element_4"), while deterministic execution primitives resolve safe centroid coordinates adjusted for OS DPI scaling.

1. Problem Identification & Root-Cause Analysis

Through empirical benchmarking of modern vision-action models across desktop and web workflows, five foundational systemic failure modes were identified:

1.1 Problem 1: Perception Fragility & Coordinate Drift

Standard VLM computer-use agents prompt a model to output direct coordinate pairs: click(x, y). In real operating environments, this approach fails due to:

  • DPI Scaling Quantization: Modern Windows systems utilize non-integer scaling (125%, 150%, 175%). High-resolution screenshots (1080p, 1440p, 4K) are downsampled to fit VLM context limits. Projecting predicted normalized coordinates back to native hardware space introduces an error margin of 10 to 30 pixels, easily missing compact buttons or hitting dead zones.
  • Textless & Miniature UI Targets: Icons such as minimize/maximize, checkboxes, toggle switches, and dropdown arrows lack textual labels and measure under 16x16 pixels, frequently escaping detection in downsampled images.
  • Custom Renderers: Electron, Qt, Flutter, and Canvas applications do not expose standard DOM structures, rendering pure DOM tools blind and pure vision models prone to hallucinated boundaries.

1.2 Problem 2: Open-Loop Execution & The Amnesiac Failure Loop

Existing GUI agents typically dispatch an action and immediately assume success without inspecting post-action consequences:

State St  ⟶  Action At  ⟶  OS Dispatch  ⟶  Assume St+1 Succeeded
  • Asynchronous UI Latency: Applications experience network delays, background rendering, and loading animations. Actions dispatched before the UI finishes rendering are silently dropped.
  • Modal Dialogs & Focus Stealing: UAC prompts, cookie banners, and save dialogs intercept clicks. Without post-action verification, the agent continues executing downstream steps on an invalid mental state, entering repetitive "death loops" that burn tokens until hard timeout.

1.3 Problem 3: The Amnesia Problem (Zero Cross-Session Learning)

Current LLM agents operate with purely ephemeral contexts:

  • Zero Experiential Accumulation: If an agent expends 10 trial-and-error steps discovering that an internal enterprise app requires double-clicking an obscure icon, that knowledge is discarded when the session ends.
  • Repetitive Mistakes: On subsequent runs of the identical task, the agent repeats the exact same sequence of failures, incurring redundant latency and token costs.

1.4 Problem 4: Platform Silos (Web vs. Desktop Fragmentation)

  • Web-Only Tools: Confined to the browser DOM; incapable of handling desktop file dialogs, system settings, or native apps (Excel, ERP software, IDEs).
  • Desktop-Only Tools: Treat browser windows as dumb pixels, ignoring the deterministic DOM tree, leading to slow and brittle visual clicking.
  • Real-World Enterprise Reality: Real workflows inherently cross boundaries (e.g., download report in Chrome → parse in Excel → upload to desktop accounting software).

1.5 Problem 5: Economic Viability, Token Latency & Safety Hazards

  • The "Token Tax": Streaming full-screen 1080p/4K screenshots (1,600+ tokens per image) on every click costs significant API fees and triggers rate limits.
  • Sluggish Latency: Multimodal API calls require 2 to 5 seconds per step, making 20-step tasks take several minutes.
  • Safety Hazards: Unrestricted OS keyboard/mouse automation risks accidental data destruction (Shift+Delete), sending unsent emails, or closing unsaved work without a kill switch.

3. Detailed Requirements Specification

3.1 Functional Requirements (FR)

Req ID Feature Name Detailed Functional Specification
FR-1 Multi-Modal Hybrid Perception Capture desktop screen via mss (≤ 150ms); extract visual elements with VLM; run local OCR fallback (pytesseract); extract Windows UIA and Playwright DOM trees; merge elements via IoU ≥ 0.5 into a unified UIState.
FR-2 Hierarchical Planning Decompose natural language goal into sub-goals; generate actions referencing semantic element IDs (e.g., target_id: "element_4") rather than raw pixels.
FR-3 Controlled Execution Primitives Execute mouse clicks, typing, hotkeys (Ctrl+C, Alt+Tab), scrolling via pyautogui; execute browser actions via Playwright; manage windows via pywinauto; auto-scale coordinates by OS DPI factor.
FR-4 Closed-Loop Verification Two-tier outcome check: Tier 1 (fast deterministic title/URL/DOM change ≤ 200ms) + Tier 2 (visual delta comparison); classify outcome as SUCCESS, NOOP, UNEXPECTED_MODAL, WRONG_NAVIGATION, or SYSTEM_ERROR.
FR-5 Autonomous Recovery Diagnose root cause upon failure; trigger adaptive tactics (dismiss modal, fallback from DOM to UIA/VLM, keyboard Tab navigation, or backtrack via Esc); enforce 3-retry cap per step.
FR-6 Dual-Layer Memory System Store full step trajectories in relational SQLite; embed goals, screen summaries, and key UI states in ChromaDB; retrieve top-3 similar past experiences via cosine similarity before planning.
FR-7 Self-Improvement Engine Post-task trajectory reflection; synthesize machine-actionable heuristics: IF [Context] THEN [Strategy]; dynamically update modality preference weights per application.
FR-8 Dashboard & Safety Switch FastAPI WebSocket live screen streaming with bounding box overlays; interactive pause/step controls; OS-level emergency stop hook (Ctrl+Alt+Esc) halting automation in ≤ 50ms.

3.2 Non-Functional Requirements (NFR)

Category Requirement Quantitative Target / Constraint
NFR-1: Performance Perception Cycle Latency Screen capture + hybrid OCR/UIA extraction completes in ≤ 1.2 seconds.
NFR-1: Performance Planning Cycle Latency Reasoning model (Gemini 2.5 Flash / Groq LLaMA-3.3-70b) responds in ≤ 2.0 seconds.
NFR-1: Performance Memory Search Latency ChromaDB vector similarity search executes in ≤ 100 milliseconds.
NFR-2: Safety Destructive Action Guard Commands with format, del /s, rmdir, or checkout buttons pause and prompt user.
NFR-2: Safety Kill-Switch Preemption Pressing Ctrl+Alt+Esc terminates action execution within ≤ 50 milliseconds.
NFR-3: Cost Zero-Cost Base Operation 100% operational on free-tier APIs (Gemini 2.5 Flash free quota, Groq, OpenRouter free models).
NFR-4: Robustness Fail-Safe UI Release On any unhandled exception, automatically release all pressed mouse buttons and keyboard keys.
NFR-5: Modularity Pydantic Data Contracts 100% of data models (UIState, UIElement, BBox, Action) validated via Pydantic v2.

5. Conclusion & Architectural Readiness

This report establishes the complete problem formulation, stakeholder justification, functional specifications, and non-functional performance envelopes for SIVAC. The architecture directly resolves the core vulnerabilities that inhibit existing GUI agents by coupling hybrid multi-modal perception, two-tier verification, and episodic self-improvement.
